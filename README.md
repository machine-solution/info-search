# Wikisearch: корпусно-независимый поисковик на C++

Учебный поисковый движок первого майлстоуна: собственный обратный индекс,
потоковая сборка большого корпуса, компактные postings и быстрый булев retrieval.
Название бинарника историческое; код не знает, какой датасет индексируется.

## Готовый результат

- **10 672 101 полноразмерный веб-документ** — на 672 101 больше требования;
- 9 672 101 документов FineWeb-Edu и 1 000 000 документов FineWeb;
- **8 309 234 450 нормализованных токенов** нашего C++-токенайзера;
- в среднем 778,6 токена на документ;
- 12 334 076 уникальных термов и 3 238 747 318 пар `терм-документ`;
- собственный сегментный обратный индекс на C++20;
- delta+varint postings, k-way merge и индивидуальное zlib-сжатие текстов;
- булев язык `AND` / `OR` / `NOT` со скобками и ленивым деревом исполнения;
- batch-интерфейс: формулы из файла, выдача и latency-статистика в JSONL;
- локальный web UI с результатами, latency и деревом запроса;
- реальные URL источников в выдаче;
- индекс: `index/learning-web-10m/`, 30,11 GB (28,04 GiB);
- сборка: 7 448,75 с — 2:04:08, peak RSS 278,4 MiB;
- benchmark из 20 AND-запросов: p50 0,303 мс, p95 0,659 мс,
  max 0,721 мс;
- холодная загрузка worker-а: 2,78 с, peak RSS 773,1 MiB.

Средний размер документа сопоставим с англоязычной Wikipedia: 778,6 нормализованного
токена на документ против примерно 730 слов на статью. Это оценочное сравнение:
методики подсчёта различаются.

## Что умеет текущая версия

Документы и запросы проходят один анализатор: UTF-8 токенизация, lowercase для
русских и латинских букв, сохранение цифр. Булевый парсер строит дерево
с приоритетом `NOT` > `AND` > `OR`; соседние слова означают `AND`. Узлы дерева
лениво сливают отсортированные postings и останавливаются после top-K. `A AND NOT B`
исполняется как потоковая разность, без материализации дополнения всей коллекции.

Результаты пока упорядочены по внутреннему `doc_id`, а не по релевантности. Это
осознанная граница milestone 1. BM25, TF, словопозиции, phrase/proximity и оценка
качества относятся к следующему этапу.

## Быстрый запуск

Нужны `g++` с C++20, `make` и `zlib`.

```bash
make
make test
./build/wikisearch search --index index/learning-web-10m
```

Локальный web-интерфейс:

```bash
./build/wikisearch serve --index index/learning-web-10m
```

После загрузки индекса откройте <http://127.0.0.1:8080>. Сервер слушает только
loopback-интерфейс и не публикует индекс в локальную сеть. Страница показывает
внутренний `doc_id`, внешний ID, заголовок, ссылку, фрагмент текста, время поиска и
AST булевой формулы. Лимит выдачи — от 1 до 100 документов. Другой порт и каталог
статических файлов задаются через `--port` и `--web-root`.

Одиночный запрос:

```bash
./build/wikisearch search \
  --index index/learning-web-10m \
  --query 'artificial AND (intelligence OR learning) AND NOT fiction' \
  --top 10
```

Пакет запросов (одна булева формула на строку):

```bash
./build/wikisearch batch \
  --index index/learning-web-10m \
  --input examples/boolean_queries.txt \
  --output results.jsonl \
  --top 10
```

Каждая строка `results.jsonl` содержит формулу, выдачу, `search_ms` и
`total_ms`; последняя строка содержит mean/p50/p95/max. Потоки поддерживаются
через `--input -` и `--output -`.

Каждый FineWeb-документ хранит внешний ID, заголовок, URL и сжатый полный текст.
ID кликабелен в терминалах с OSC 8; обычный URL всегда печатается отдельной строкой.

## Воспроизводимая сборка корпуса

```bash
bash scripts/setup_fineweb_adapter.sh
make -j4
bash scripts/build_learning_web_index.sh
```

Скрипт скачивает только один Parquet shard за раз, проверяет его, передаёт записи
потоком в C++ и удаляет shard. Загрузка возобновляется после сетевого обрыва. Python
нужен только для чтения контейнера Parquet; JSON parser, токенизация, document store,
обратный индекс, merge и поиск реализованы на C++.

Benchmark:

```bash
bash scripts/benchmark.sh \
  index/learning-web-10m \
  tests/benchmark_queries_learning_web.txt
```

## Формат входа и независимость от корпуса

Индексатор принимает JSONL:

```json
{"id":"doc-42","title":"Example","url":"https://example.org/42","text":"Full text"}
```

Обязателен `text`; `id`, `title` и `url` используются для выдачи. Для обратной
совместимости вместо `id` принимается `docid`. В ядре нет специальных веток для
FineWeb, Wikipedia или MIRACL.

## Структура

- `src/jsonl.*` — потоковый JSONL parser;
- `src/tokenizer.*` — единый анализатор документов и запросов;
- `src/index_builder.*` — batch-сегменты, document store и k-way merge;
- `src/query_parser.*` — lexer, грамматика и AST булевой формулы;
- `src/search_engine.*` — lexicon, postings cursors и ленивые AND/OR/NOT iterators;
- `src/web_server.*` — loopback HTTP API и сериализация AST/выдачи в JSON;
- `src/main.cpp` — CLI и формат выдачи;
- `web/` — статический интерфейс без внешних зависимостей;
- `scripts/` — адаптеры и воспроизводимые сборки;
- `tests/` — smoke corpus и benchmark-запросы;
- `docs/` — техническая документация формата и архитектуры;
- `index/learning-web-10m/` — готовый основной индекс;

## Про источник и этику

FineWeb — очищенный и дедуплицированный текст Common Crawl, FineWeb-Edu дополнительно
отфильтрован по образовательному качеству. Это более аккуратный выбор, чем случайный
web crawl, но он не гарантирует отсутствие спорного содержания. Датасет выпущен под
ODC-By 1.0; права на отдельные исходные страницы остаются у их владельцев. URL
сохраняются для атрибуции и проверки источника, исходные Parquet-файлы после сборки
на ноутбуке не хранятся.
