## Query-time

Команда:

```bash
bash scripts/benchmark.sh \
  index/learning-web-10m \
  tests/benchmark_queries_learning_web.txt
```

20 английских AND-запросов, один загруженный worker, `top=1`:

- mean: 0,331 мс;
- p50: 0,303 мс;
- p95: 0,659 мс;
- max: 0,721 мс.

Повтор той же серии при прогретом файловом кеше: mean 0,018 мс, p50 0,016 мс,
p95 0,021 мс, max 0,054 мс. Для обещаний по latency выше используются более
консервативные значения первого запуска.

Время включает retrieval, но не холодную загрузку словаря и offsets. Отдельный
холодный запуск с одним запросом:

- wall time процесса: 2,78 с;
- peak RSS: 791 676 KiB = 773,1 MiB;
- сам `AND("climate change")`: 0,083 мс.

Пример `AND("artificial intelligence")`, `top=3`: 0,588 мс.

После добавления булева дерева 02.11.2026 прогнан batch из семи разных формул
`AND` / `OR` / `NOT`, `top=5`:

```bash
./build/wikisearch batch \
  --index index/learning-web-10m \
  --input examples/boolean_queries.txt \
  --output results.jsonl \
  --top 5
```

- 7/7 формул выполнены успешно;
- mean search: 0,873 мс;
- p50: 1,045 мс;
- p95/max: 1,411 мс;
- batch wall time после загрузки индекса: 22,418 мс, включая чтение и распаковку
  35 документов для выдачи.

Это тоже единичный локальный замер, а не стабильная оценка p95 продакшен-нагрузки.

## Диск на ноутбуке

- сохранённый старый MIRACL passage baseline: 22 GiB;
- вместе два индекса: около 51 GiB;

## Что измерять на следующем этапе

1. Не менее 1 000 запросов с p50/p95/p99 отдельно для AND и OR.
2. Число прочитанных postings и байт на запрос.
3. Throughput нескольких workers.
4. Recall@K, MRR@10 и nDCG@10 на зафиксированном eval dataset.
5. Вклад BM25, phrase/proximity и остальных фичей через ablation.
