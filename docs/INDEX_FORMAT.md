# Формат индекса Wikisearch

Все целые числа фиксированного размера записываются в native little-endian формате
текущей платформы. Переменные целые — unsigned LEB128/varint.

## `docs.bin`

- magic `WDOC1`;
- `uint32 format_version`;
- версия 1 (читается для обратной совместимости) хранит последовательно:
  - varint-длина и байты внешнего `docid`;
  - varint-длина и UTF-8 байты `title`;
  - varint-длина и UTF-8 байты `text`.
- версия 2 записывает:
  - varint-длина и байты внешнего `id`;
  - varint-длина и UTF-8 байты `title`;
  - varint-длина и UTF-8 байты исходного `url`;
  - varint исходного размера текста;
  - varint сжатого размера текста;
  - независимо сжатые zlib level 1 байты `text`.

Независимое сжатие каждого документа сохраняет random access: для показа результата
не нужно распаковывать соседние документы или весь document store.

`docs.offsets` содержит по одному абсолютному `uint64`-смещению в `docs.bin` на
каждый внутренний `doc_id`. Это даёт O(1) random access без JSON-парсинга во время
поиска.

## Временный сегмент

- magic `WSEG1`;
- записи отсортированы лексикографически по терму;
- запись: varint-длина терма, UTF-8 байты терма, varint `df`, затем `df` delta-varint
  идентификаторов документов.

Размер batch задаётся параметром индексатора; полный профиль строился сегментами по
100 000 документов. Поэтому RAM индексатора не зависит линейно от размера корпуса.

## `metadata.txt`

Кроме версии анализатора и кодирования содержит статистику сборки: число документов,
термов, токенов, пар `терм-документ`, запрошенный лимит и wall time. `terms` — число
различных слов, поэтому оно не обязано быть больше числа документов.

## `lexicon.bin`

- magic `WLEX1`;
- `uint32 format_version`;
- `uint64 document_count`;
- `uint64 term_count`;
- для каждого терма:
  - varint-длина и байты терма;
  - `uint64 offset` в `postings.bin`;
  - `uint64 byte_size` списка;
  - `uint32 document_frequency`.

## `postings.bin`

Последовательность postings lists без промежутков. Каждый список состоит только из
delta-varint `doc_id`; границы и число элементов находятся в словаре.

## Инварианты

- внутренние `doc_id` монотонно растут с нуля;
- в одном postings list нет повторов, идентификаторы строго возрастают;
- анализатор документа и запроса один и тот же;
- недостающий терм даёт пустой список, а не ошибку;
- временные сегменты удаляются только после успешного финального merge.
